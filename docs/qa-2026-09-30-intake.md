## Confirmed causes and changes

- Home previously created requirements without a template; template upload was a separate path.
- Old DOCX parsing assumed the first two columns were number/TOR. Intake now reads explicitly selected columns.
- A low-score unselected Word table could retain old answers. Source-like unselected tables are removed independently of header-score threshold.
- Descendant versus direct table-row indices disagreed when prefix content had a nested table. Source/template/export use direct rows for the selected table.
- Fixed-distance PDF header grouping merged narrow columns and included body proposal text. Grid columns and physical header bounds now determine source cells where detected.
- White glyphs split a filled header into raster bands. Header-band boundaries are merged rather than treated as separate row borders.
- PDF coordinate fields used an HTML step incompatible with their detected decimal defaults. Boundary controls now accept that precision.
- Replacing a shared template could delete the original. File deletion retains an ID still used by torDocId.
- Batch assessment did not navigate a currently selected clause when its ID stayed the same. It now focuses the active clause using its latest evidence.

## Practical limits

This is a scoped functional/data-integrity audit, not a guarantee for every TOR sentence or document layout. Intake requires readable text; OCR is outside this change. PDF boundaries must be checked in preview; mixed incompatible DOCX tables are selected as a compatible group and unselected Comply tables are excluded from output. Cross-format layout remains approximate.

The constrained host had 7.63 GB free disk and 0.38 GB free RAM at the initial measurement. No new dependency tree, browser binary, container, admin tool, or local model was installed. Local lint/build were not run; Node tests, syntax checks, cloud build and browser/artifact checks were used.
