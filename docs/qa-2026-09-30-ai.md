## Confirmed causes fixed during review

- Provider success objects were forwarded after partial validation, including unknown metadata. Reproduced with a synthetic sentinel; relay now returns only canonical documented fields.
- Cancellation originally covered only registered fetch controllers. A delayed file/render preflight could resume using a new key. Jobs now capture and verify a provider revision before transmission, after response, and before applying draft text.
- Typed unsubmitted keys could survive clear/pagehide. Password inputs reset synchronously on clear/pagehide and unmount.
- An old draft could remain reviewed after provider/model/consent changes. Session changes clear it and application verifies its captured ticket.
- Browser QA found duplicate physical excerpts from a saved highlight plus the search index. A failing regression reproduced it; the AI shortlist now sends that source region once to avoid duplicate judgments/cost.
- Live OpenAI HTTP 429 required distinguishing billing quota from request-rate limits. Only known public error-code enums are exposed; raw provider messages remain discarded.
- User requested blogger research. [CodeRouter](https://www.coderouter.io/blog/openai-429-insufficient-quota-error-fix) and [Continuum](https://continuumcode.ai/guides/openai-insufficient-quota/) were read as troubleshooting context; technical changes follow [OpenAI's current error guide](https://developers.openai.com/api/docs/guides/error-codes). A failing regression confirmed the older three-code allowlist omitted credit_balance_exhausted and current organization/project limit codes; the allowlist and safe action hints now cover them.

## Limits and host

Simulated OpenAI success does not establish real OpenAI inference or OCR accuracy. Model listing proves listing authorization only. Live TypeSafe success is one synthetic clause/excerpt, not a Thai semantic benchmark. 4–10-user load capacity and arbitrary customer documents are untested.

Resolution for the observed OpenAI code: check the prepaid API balance of the organization associated with the key and add credits through its authorized billing owner; retry a small request after the updated balance takes effect. Retrying or rotating keys in the same unfunded organization does not restore credits. No billing settings or purchases were performed.

Direct browser Cookies/localStorage/sessionStorage inspection via raw CDP was unavailable in this instrument. Storage claims are supported by the separate memory-only code/vault tests, tab lifecycle checks and actual project-archive inspection; this does not attest to the user's extensions or OS/browser internals.

Keys are not persisted by this app. AES-GCM does not defeat XSS/hostile extensions or guarantee erasure from browser/OS memory. Browser storage controls do not establish provider or hosting-platform retention; OpenAI requests use store:false.

Comply-table intake still needs readable text. OpenAI OCR reads an original TOR page or an existing evidence crop; page/box geometry is code-owned and human review remains required.

Initial host check: 7.06 GB disk free, 0.45 GB RAM free. No packages, browser binaries, models, containers, or admin tools installed. Cloud build is used in place of local Next dependency installation.
