## Confirmed causes fixed during review

- Provider success objects were forwarded after partial validation, including unknown metadata. Reproduced with a synthetic sentinel; relay now returns only canonical documented fields.
- Cancellation originally covered only registered fetch controllers. A delayed file/render preflight could resume using a new key. Jobs now capture and verify a provider revision before transmission, after response, and before applying draft text.
- Typed unsubmitted keys could survive clear/pagehide. Password inputs reset synchronously on clear/pagehide and unmount.
- An old draft could remain reviewed after provider/model/consent changes. Session changes clear it and application verifies its captured ticket.

## Limits and host

No live paid-provider success or accuracy benchmark is implied by a simulated upstream. Model listing proves listing authorization only. Thai semantic accuracy and 4–10-user load capacity need real representative data.

Keys are not persisted by this app. AES-GCM does not defeat XSS/hostile extensions or guarantee erasure from browser/OS memory. Browser storage controls do not establish provider or hosting-platform retention; OpenAI requests use store:false.

Comply-table intake still needs readable text. OpenAI OCR reads an original TOR page or an existing evidence crop; page/box geometry is code-owned and human review remains required.

Initial host check: 7.06 GB disk free, 0.45 GB RAM free. No packages, browser binaries, models, containers, or admin tools installed. Cloud build is used in place of local Next dependency installation.
