# TOR Comply Next.js

เว็บแอพ React/Next.js สำหรับทำ Comply TOR ราชการไทย เอกสารและข้อมูลโครงการอยู่ในเบราว์เซอร์ของอุปกรณ์ที่ใช้งาน (IndexedDB และ localStorage) ไม่มีการอัปโหลด TOR หรือหลักฐานไปยังเซิร์ฟเวอร์ และไม่มีการเรียก AI API แบบเสียเงิน

## เส้นทางงาน

1. สร้างโครงการแล้วอ่าน TOR PDF/DOCX เป็นเช็กลิสต์ หน้า PDF ที่เป็นภาพใช้ OCR ไทย/อังกฤษทีละหน้า โดยให้ตรวจและแก้ผลก่อนเพิ่มข้อ
2. เพิ่มสินค้า/บริการและ PDF หลักฐาน ระบบแนะนำเอกสารที่มีคำตรงกันจากไฟล์ที่ผู้ใช้เพิ่ม ไม่ตัดสินผล Comply แทนคน
3. เลือกข้อ TOR และลากกรอบบนหน้า PDF เพื่อทำไฮไลต์ พร้อมระบุเลขหน้าที่พิมพ์ในเอกสาร
4. เขียนรายละเอียดที่เสนอ ยืนยันผลเปรียบเทียบ แล้วส่งออกตาราง Word/Excel สี่คอลัมน์และ PDF หลักฐานที่ทำเครื่องหมายแล้ว

ผล `ตรงตามข้อกำหนด` ต้องมีรายละเอียดที่เสนอและหลักฐานที่ผูกไว้ ข้อมูลอยู่เฉพาะเบราว์เซอร์นั้น ไม่ซิงก์ระหว่างโน้ตบุ๊กกับโทรศัพท์

## พัฒนาและตรวจ

ต้องใช้ Node.js 22 และติดตั้ง dependencies ในโฟลเดอร์ `web`:

```sh
npm install
npm run test
npm run build
npm run dev
```

บนเครื่อง HQ-NB-BS-02 พื้นที่ว่างต่ำกว่าเกณฑ์ 15 GB จึงไม่ติดตั้งชุด Next.js ลงเครื่องในรอบนี้ ใช้ GitHub Actions ใน `.github/workflows/web.yml` เพื่อตรวจ test/build บน cloud

## ข้อจำกัด

- OCR/การแยกเลขข้ออาจผิด ต้องเทียบ TOR ต้นฉบับก่อนยืนยัน
- เอกสารหลักฐานสำหรับไฮไลต์ต้องเป็น PDF หน้า PDF ที่หมุนอยู่ยังไม่รองรับการส่งออกเครื่องหมาย
- ต้องอัปโหลดสินค้าและ datasheet เอง ระบบไม่ค้นเว็บผู้ผลิตหรือเติมราคา
- ไฟล์ที่เก็บในเบราว์เซอร์อาจหายเมื่อผู้ใช้ล้างข้อมูลเว็บไซต์ ควรส่งออกงานก่อนล้างข้อมูล

PDF.js และไฟล์ worker/wasm มาจาก [Mozilla PDF.js](https://github.com/mozilla/pdf.js) พร้อมใบอนุญาตใน `public/pdfjs-LICENSE` และ `public/wasm/` ไฟล์ OCR มาจาก [Tesseract tessdata_fast](https://github.com/tesseract-ocr/tessdata_fast) พร้อมใบอนุญาตใน `public/ocr-data/LICENSE` ฟอนต์ไทยของ PDF ที่ทำเครื่องหมายมาจาก [Noto Sans Thai](https://github.com/notofonts/noto-fonts) พร้อม `public/fonts/OFL.txt` ไม่มีไฟล์ TOR ตัวอย่างหรือเอกสารลูกค้าถูกนำเข้า repo
