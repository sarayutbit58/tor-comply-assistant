# TOR Comply notebook workspace

## ใช้งาน

1. เริ่มจาก **ตาราง Comply + แม่แบบ** เลือก DOCX/PDF/XLSX แล้วกดอ่านตาราง ตรวจ preview และเลือกคอลัมน์เลขข้อกับข้อกำหนด กดยืนยันคอลัมน์แล้วสร้างโครงการ ไฟล์เดียวเป็นต้นฉบับและแม่แบบ ช่องคำตอบ/ผล/อ้างอิงเก่าเริ่มใหม่ทั้งหมด หรือเลือกโหมด TOR ต้นฉบับเพื่อใช้ขั้นตอนเดิม
2. ตรวจและยืนยันข้อความ TOR แต่ละข้อก่อน Auto ตารางที่มีหลายตารางย่อยนำเข้ากลุ่มที่หัวคอลัมน์เดียวกันได้ PDF ต้องมี text layer; รอบนี้ไม่เพิ่ม OCR ในการนำเข้าตาราง หากขอบคอลัมน์อ่านผิดให้ปรับใน preview หรือใช้ DOCX/XLSX
3. เพิ่ม **สินค้า** (ยี่ห้อ/รุ่น) หรือ **บริการ** (ผู้ให้บริการ จุดให้บริการ รายละเอียด) แล้วจัดประเภทไฟล์หลักฐานเป็นสินค้า บริการ หรือคุณสมบัติผู้ยื่น ไฟล์หลักฐานที่ทำไฮไลต์ใช้ PDF
4. คลิกแถวตาราง เลือกรายการที่จะใช้ร่วมกัน ระบบจัดอันดับคำที่ตรงในเอกสารที่แนบและเปิด TOR/หลักฐานตามแถว
5. ใช้ “ค้นหลักฐานและเสนอผล” หรือ Auto เพื่ออ่านเหตุผลรายเงื่อนไข สามารถลากกรอบเองและใช้จุดเดียวร่วมกับข้ออื่นได้ เลขข้อบน PDF รวมไว้ในเครื่องหมายเดียว
6. หลักฐานสแกนเลือก OCR ในเครื่องหรือกรอกข้อความจากกรอบเองได้โดยไม่ใช้คีย์ ตรวจข้อความที่อ้างก่อนยืนยัน/ส่งออก; cloud OCR เป็นส่วนเสริมที่เลือกเอง
7. อัปโหลดแม่แบบหนึ่งไฟล์ DOCX/PDF/XLSX ตรวจการจับคู่หัวคอลัมน์ แล้วส่งออก PDF, Word หรือ Excel
8. “สำรองโครงการ” สร้าง .torproj รวม TOR หลักฐาน แม่แบบ ไฮไลต์ คำตอบ และสถานะ นำเข้าจากหน้าแรกเป็นโครงการใหม่ โดยไม่เขียนทับโครงการเดิม

## กฎและผลตัดสิน

- โหมดหลักเป็นตรวจเองหรือ Auto และเปลี่ยนเฉพาะข้อได้
- TOR/แม่แบบไม่อยู่ในดัชนีหลักฐานและใช้ยืนยันผลไม่ได้
- ตรวจ keywords, คำปฏิเสธ, หน่วยบิต/ไบต์, ค่าขั้นต่ำ/สูงสุด และคุณสมบัติที่ต้องตรง มีหน่วย/ศัพท์พื้นฐานสำหรับ Internet, Network, Server, CCTV, Security
- 25G ไม่ยืนยันว่ารองรับ 10G ต้องมีค่าหรือข้อความยืนยันความสามารถนั้น
- หลักฐานต้องครบทุกรายการที่เลือกใช้ร่วมกัน ข้อมูลที่ขัดแย้งหรือยังพิสูจน์ไม่ได้คงสถานะรอตรวจ
- กฎใช้การเทียบข้อความและเงื่อนไขที่รองรับ ไม่ได้พิสูจน์ความถูกต้องของหนังสือรับรองหรือความสามารถส่งมอบจริง AI เป็นตัวเลือกช่วยตรวจในช่วงทดสอบ ไม่ตัดสินผ่านแทนกฎ

## API AI ช่วงทดสอบ — 2026-09-30

เปิด AI / API Keys กรอก OpenAI สำหรับ OCR/LLM และ TypeSafe สำหรับ System One แต่ละคีย์เรียกรายการโมเดลใหม่ทันที เลือก LLM และ OCR แยกกันจากสูงสุด 5 รุ่นที่รองรับในบัญชี เริ่มรุ่นงานง่ายและเปลี่ยนเองเมื่องานยากขึ้น TypeSafe แสดง Jev stable โดยไม่มี picker รายการสำเร็จตรวจสิทธิ์ listing เท่านั้น งานจริงอาจมี quota/สิทธิ์ inference ต่างกัน

เปิดอนุญาตส่งข้อมูล จากนั้นใช้ AI ช่วยข้อนี้เพื่อแยก TOR/ร่างคำตอบ หรือจัดอันดับ/ตรวจความหมายของข้อความหลักฐานที่เลือก ไม่มีการเลือกสินค้าแทน Presales หรือเปลี่ยน Comply จากคะแนน AI เอง ร่างคำตอบต้องตรวจและกดยืนยันใช้ก่อน พิกัดและเอกสารอ้างต้องมาจากไฟล์จริง

คีย์ใช้ AES-GCM ในหน่วยความจำแท็บ ไม่เก็บใน Cookies, Cache, browser storage หรือ .torproj รีโหลด/ปิดแท็บต้องกรอกใหม่ และล้างคีย์เองได้ เซิร์ฟเวอร์ส่งต่อผ่าน HTTPS แบบไม่บันทึกคีย์ OpenAI requests ใช้ store:false; นโยบายเก็บข้อมูลของผู้ให้บริการแยกจากการเก็บของแอป การเข้ารหัสไม่ป้องกัน XSS/ส่วนขยายอันตรายหรือรับประกันการลบจาก OS memory จึงใช้คีย์ช่วงทดสอบตามความเหมาะสม

ผลทดสอบวันที่ 2026-09-30: TypeSafe เรียก Jev จริงได้; OpenAI ดึงโมเดลได้แต่ inference คืน credit_balance_exhausted ต้องตรวจ/เติมเครดิต API ขององค์กรที่ออกคีย์ก่อน ไม่แก้ด้วย retry หรือเปลี่ยนโมเดล รายละเอียดขอบเขตตรวจและผลทดสอบอยู่ใน [QA API AI](../docs/qa-2026-09-30-ai.md)

### OpenRouter สำหรับ LLM และ OCR

กรอก OpenRouter API Key แล้วกดตรวจคีย์/ดึงโมเดลใหม่ จากนั้นเลือกผู้ให้บริการ LLM และ OCR เป็น OpenRouter ได้แยกกัน รุ่นเริ่มต้นเป็นงานง่าย OCR มีเฉพาะรุ่นรับภาพได้; LLM มีเฉพาะรุ่นรองรับ structured output ภายในชุดแนะนำ คีย์และตัวเลือกไม่ติดไปกับไฟล์โครงการ ปิดแท็บ/รีโหลดต้องกรอกใหม่ ไม่มีการเลือกใช้ OpenAI แทนเมื่อ OpenRouter ผิดพลาด

เซิร์ฟเวอร์ตรวจ endpoint ของคีย์ก่อนอ่าน catalogue สาธารณะ งานจริงอาจถูกจำกัดด้วยเครดิต/วงเงิน/สิทธิ์โมเดลหรือ privacy routing ของบัญชี OpenRouter ใช้บัญชีและเครดิตของ OpenRouter เอง ระบบแสดง error ให้แก้ก่อนเรียกใหม่ รายงานตรวจอยู่ใน [QA OpenRouter](../docs/qa-2026-09-30-openrouter.md)

ตรวจวันที่ 2026-09-30: คีย์ทดสอบ OpenRouter ดึงโมเดลได้ และ google/gemini-3.5-flash-lite ทำ LLM พร้อมอ้างหลักฐานและ OCR ไทยจากหน้า 2 สำเร็จ คีย์ถูกล้างหลังทดสอบ รุ่นอื่นและความแม่นยำบน TOR จริงยังต้องประเมินแยก

## รูปแบบและข้อจำกัดที่แสดงในแอพ

- เน้นโน้ตบุ๊ก หน้าทำงานกว้างขั้นต่ำ 1080px ปรับความกว้างสามช่องได้
- PDF/DOCX รักษารูปแบบแม่แบบเท่าที่อ่านได้; native DOCX เก็บตารางและหัว–ท้ายหน้าเดิม การข้ามชนิดไฟล์เป็นการจัดหน้าใหม่ ตรวจ preview/หัวคอลัมน์ก่อนส่งออก
- Excel เป็นตารางแก้ไข/กรองได้ ไม่มีการรวมเซลล์ในแถวข้อมูล
- แม่แบบ PDF อ่านโครงจากหน้าแรก หากอ่านไม่ครบต้องกำหนดหัวคอลัมน์ในหน้าตั้งค่า; ไม่ใช้คำตอบเก่าเป็นข้อมูลหรือหลักฐาน
- ตาราง Comply PDF อ่านข้อมูลหลายหน้าโดยใช้ขอบคอลัมน์และเส้นตาราง พร้อมแจ้งเมื่อข้อความคร่อมคอลัมน์ที่เลือก; DOCX/XLSX คงตำแหน่งคอลัมน์แม้สลับลำดับหรือมีเซลล์ว่าง
- TOR DOCX แสดงข้อความข้อกำหนดในช่องต้นฉบับและดาวน์โหลดไฟล์เดิมได้ ไม่มีการอ้างเลขหน้า PDF ที่ไม่มีอยู่จริง
- PDF หลักฐานที่หมุนหน้ามีข้อจำกัดในการ export annotation ระบบแจ้งก่อนสร้างไฟล์
- ไฟล์เดี่ยวจำกัด 40 MB; โครงการสำรองรวมไฟล์ต้นฉบับไม่เกิน 160 MB ข้อมูลในเว็บไซต์อาจหายหากล้าง browser storage ต้องสำรองเป็นระยะ
- ฟอนต์ PDF ใช้ Noto Sans Thai และ Helvetica รูปแบบการตัดบรรทัดอาจต่างจาก Microsoft Word

- หน้าทำงานมีเพิ่ม/แก้/ลบข้อ ตรวจแก้การอ่านก่อน–หลัง แก้สินค้า/บริการและกลุ่มไฟล์ แก้ข้อความหลักฐาน แชร์จุดอ้างอิง และย้อนกลับรายการล่าสุดในแท็บนี้
- OCR ไทย/อังกฤษในเครื่องเป็นค่าเริ่มต้น และกรอกข้อความจากภาพเองได้ หน้าที่อ่านไม่ครบต้องตรวจทุกข้อและยืนยันทั้งหน้าโดยระบุเหตุผล

- OCR อาจอ่านชื่อเทคนิคผิด ต้องเทียบภาพและแก้ก่อนยืนยัน ระบบเก็บข้อความ OCR เดิมและข้อความที่ยอมรับไว้แยกกัน
- ไฟล์เล็กมีลิงก์รับไฟล์ซ้ำในหน้าทำงาน 2 นาที Word ตรวจเนื้อหาและโครงสร้างแล้ว แต่ยังไม่ได้ตรวจการแบ่งหน้าใน Word/LibreOffice บนเครื่องนี้
